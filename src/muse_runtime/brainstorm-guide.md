# Jev 构思评价

当前构思负责人使用本工具比较具体候选，判断哪些方向值得推荐、补强或重构，并把作者反馈用于下一轮创作。工具返回结构化建议；人物和情节的修改、推荐理由、作者选择与产物回写由原创作流程负责。

## 调用时机与作品模式

在实质候选已经形成、准备推荐或重做被退回的构思时使用。先修正已有材料能确定的事实与因果错误。作者已经选定方向时继续展开；例行补设定、格式调整和文字校正沿原流程完成。

读取当前作品的 `.muse/runtime.yaml`，无文件按 `standard` 执行。`standard` 不读密钥、不发送请求，原流程仍可比较、修订和推荐。`jev` 优先使用执行进程的 `MUSE_JEV_API_KEY` 调用官方；官方额度不足或限流时，使用 `MUSE_JEV_TUZI_API_KEY` 切换 Tuzi；作品模式设置和密钥管理沿安装方配置，本命令不自动启用模式。连载的卷向或章级共创使用系列根，独立长短篇使用对应作品根；显式传入目录，不从 cwd 或上级作品继承。

```bash
python3 -m muse_runtime brainstorm evaluate --work-dir <work_dir> --input <round.json>
```

命令输出 JSON；正常评价或标准模式跳过返回 0，输入、配置或评价错误返回非零。`python3 -m muse_runtime brainstorm guide` 只读取本指南，不读取作品、密钥或调用服务。运行包须安装在执行这些命令的同一 Python 环境。

## 官方优先与备用通道

检索与构思共用同一客户端：官方 `jev-1.13.0` 优先，备用 Tuzi `/v1/systemone` 使用 `jev-1.13`。官方 HTTP 402、明确的额度不足错误或 HTTP 429 触发备用；429 表示限流，不等于余额耗尽。鉴权、参数、网络和未知服务错误保持可见，不因此切换通道。

同一客户端/检索批次发现官方容量不足后，后续请求使用 Tuzi；已经在途的官方请求可继续完成。新批次或下一次构思调用重新优先官方，使充值或限流恢复后能够自动回到官方。单个请求每通道至多尝试一次，共享原请求时间预算。Tuzi 未配置或也失败时，按原流程的评价失败规则处理。Tuzi 请求上限为 32 KiB，超出时明确报错，保留完整候选，不截断文本。

结果及运行记录保留 `provider`、`model_requested`、`actual_model`、`attempts` 与切换原因；检索批次可含多个实际通道。Tuzi 别名可能映射到不同上游，实际返回模型按独立字段记录，不能把备用请求标成官方固定模型。`muse mode status` 展示优先级和最近执行记录，查看状态不读取密钥或验证余额。

## 本轮输入

从已有共创记录构造一个 JSON 对象。传输文件可置于当前作品的临时目录；本轮讨论、作者决定和来源继续使用既有记录，不据此新建审批或偏好数据库。

| 字段 | 内容 |
|---|---|
| `goal` | 必填字符串：作者原始创作意图及本轮要解决的问题、期望阅读效果。保留原话与设计负责人解释的区别 |
| `context` | 可选字符串：判断所需的已有情境、人物知识、有效设计和参考依据；没有提供的事实保持未知 |
| `constraints` | 可选字符串数组：作者已确认的方向、关系、固定结果和当前不可改动的内容 |
| `feedback` | 可选字符串数组：与本轮有关的认可、否决及理由，保留它针对的候选和范围；模型推测不记成作者反馈 |
| `candidates` | 必填非空数组，每项为 `{ "id": "候选标识", "text": "具体构思与关键剧情推演" }` |
| `questions` | 可选数组，每项为 `{ "id": "问题标识", "question": "针对各候选的一个明确是非问题" }`；同一组问题分别用于每个候选 |

候选 ID 唯一，`none_of_the_above` 与 `needs_author_preference` 为保留值。问题 ID 在本轮唯一。ID 用于对齐输入和输出，不编码排名或作者认可状态。

候选应有足够内容判断人物如何行动、局面如何变化、读者会发现什么；不同候选使用可比较的展开程度。需要来源时提供实际取得的关系和依据，主模型的自荐结论与修饰性赞语不作为证据。`context` 只提供本次决策有关的信息。

提问从本轮目标或已有失败中提炼。一个问题只判断一项具体关系；需要分别判断人物知情条件和行动后果时拆开。涉及新鲜感或情感作用的提问应说明本作所追求的效果与比较依据。`questions` 返回是非概率，程度与偏好差异由主模型结合具体内容解释，不把概率当成文学质量分。

没有额外问题时可以省略 `questions`。默认判断已经包含候选是否适合继续讨论及下一步方向，无需填满固定维度。观察性、喜剧、低对抗、人物立场稳定等创作按作者目标判断，不统一要求反转、牺牲或人物成长。

## 返回与消费

一次请求评价整组候选，返回保持输入顺序。`status: evaluated` 包含：

- `recommendation`：一个 Choice 对象，含 `choice` 和 `probabilities`。`choice` 为候选 ID，表示最值得优先讨论的方向；`none_of_the_above` 表示整组暂不适合推荐；`needs_author_preference` 表示缺少会改变推荐的作者取舍。
- `candidates[]`：各候选的 `id`、`disposition` 与 `checks`。`disposition` 为 Choice；`checks[]` 保留问题 ID 及 `noul` 是非判断概率。
- 请求标识、请求与实际模型、用量和耗时：用于核对本次实际执行。运行日志仅保留执行元数据，不保存创作文本或密钥。

| `disposition.choice` | 设计负责人下一步 |
|---|---|
| `present` | 核对候选依据后，组织推荐、成立条件和取舍，交作者判断 |
| `revise` | 保留有价值的构思，补强影响成立的行动、关系或呈现，再形成可判断的候选 |
| `rebuild` | 回到思想问题、参考关系或因果起点重新构思；保留作者已经认可的局部 |
| `need_context` | 先从已有设计、来源或共创记录补取缺失信息；缺口属于作者偏好或保留方向时再询问作者 |

这些判断是创作建议。各问题独立评价，整池推荐与逐项判断可能不一致；由设计负责人回读具体候选、问题和已有依据，定位差异，按实际缺口补强或说明取舍。`none_of_the_above` 仍需结合候选内容确定重做位置，不能只把原候选换种说法再提交。

推荐时保留值得作者判断的不同方向，包括尚不完整但有潜力的构思；低评价本身不构成自动删除依据。作者可以选取、组合、局部认可或全部否决。Jev 的选择与作者采纳分别记录；工具不会改写大纲、冻结内容、`outline_gate`、`pending` 或正式决定。

模型向作者说明的理由须能从候选、事实与来源中找到依据。Jev 只返回选择和概率，不把主模型补写的解释声称为 Jev 原话。概率与置信度描述模型判断；推荐程度、作者喜好和作品质量由具体讨论决定。

## 反馈、失败与继续

作者反馈进入下一轮的 `feedback`，已认可部分进入相应上下文或约束；只修改仍开放的关系和剧情。反馈先在当前作品及其明确范围生效。相同输入复用已有评价，目标、候选或反馈实质变化后再调用；作者选定后按原流程展开。

`status: skipped` 且原因为 `standard_mode` 表示未调用 Jev。`status: error` 或命令失败表示本轮尚未取得完整评价；没有候选判断可供采纳。缺密钥、缺运行包、服务或响应错误应说明具体未完成项，沿原流程继续可以完成的创作，不能描述成 Jev 已通过或已拒绝候选。作者明确要求先取得 Jev 结果时，报告缺件并继续不依赖该结果的工作，工具故障不新增作者审批状态。

题型依据：[Choice](https://docs.typesafe.ai/primitives/choice)、[Noul](https://docs.typesafe.ai/primitives/noul)、[概率与置信度](https://docs.typesafe.ai/confidence)。默认处置类别用于衔接现有构思流程；具体创作判断以作者目标、候选内容和实际反馈为依据。
