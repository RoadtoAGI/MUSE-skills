# Phase 1：世界构建

建立人物可以生活、判断和行动的世界。麦基《故事》第三章强调对故事世界的深入了解及其内在或然性；本阶段要让人物选择和事件后果有可信条件，同时给生活经验、关系与表达留下空间。

## 输入与取材

读取 Phase 0 的 `premise`、`genre`、`core_value` 及实际存在的要求、背景资料和来源偏好。开始填写时读[输出 schema](references/output-schema.md)；理论边界见[设定与创作限制](references/mckee-setting.md)。

世界构思未定或被退回时，按[大纲构思与回读](../story-writing/references/outline-exploration.md)推演规则怎样改变生活、关系与后果。需要补充来源时加载 `design-doc-reference`，传 `phase=1`、具体 `narrative_problem`、可用 signals 及 `canon_reference_profile`，读取返回的 `phase1_design_ref.md`。已有材料足够则复用，用户排除的参考不调用。

手选来源同时满足 `stance: prefer`、`reuse_mode: maximize_apt_reuse` 且领域含 `world_rule` 时，保留该来源已成立的机制及适用条件，再适配本作尺度、地点与人物。来源只支持部分规则时，锁定该部分，开放处按实际需要补足；模型概括不能把指定机制降为谣言或换成自创主因。采用记录沿用来源偏好与灵感台账。

## 形成可推演的世界

`setting` 说明时代、故事期限、地点及冲突层面。时代可以架空，期限可以相对，冲突层面按本作实际关系填写。尺度与作者能掌握的细节相称；广阔世界也可以通过有联系的人物和场域得到具体呈现。

`genre_conventions` 记录本作采用的类型期待。`generative_driver` 是项目用于说明持续压力或变化条件的字段：相关事件为什么发生、依什么关系运作、会怎样影响当前处境。具体问题可参考[题材材料](references/genre-worldbuilding/README.md)，按问题选择文件。

原因尚未揭示时，写清已知表现、可推断条件与未知范围。例如灾变起因可留白，但食物如何耗尽、哪些地方危险、人物凭什么判断仍需有依据。人物认知与作者设计知识分别保留。

`world_rules` 记录物理、社会及适用的心理规律。规则可以由灾变或技术派生，也可以来自独立存在的制度、习俗与人性。多种机制只要相容便可共存；说明它们真正发生作用的关系。当前剧情需要奖励、惩罚或脱险时，不能临时接出没有依据的功能；因果判别与近边界案例见[因果承重](references/mckee-setting.md#世界规则的因果承重)。

`creative_constraints` 按需说明什么做不到，以及限制怎样改变选择或结果。区别物理不可能、法律禁止、社会习惯和角色信念：违法不等于物理做不到，人物误信也不改变客观规则。

## 生活细节与研究

麦基《故事》第八章从谋生、仪式、权力和价值观理解人物生活。这些是取材角度；选择能够使处境具体、关系可感或叙述认识成立的细节。气氛、日常可信性和人物对世界的感受可以有独立作用，无需把每条细节改造成动作任务。

已有用户资料进入 `domain_knowledge`，相关生活发现进入 `daily_life`。缺少会影响当前设计的事实时，按可用宿主派发 `world-researcher`，明确作品根、问题、时代地点、已有资料和报告路径 `pipeline/world_research.md`；文件加载宿主先取得本包 agent 正文。现实专业细节可能需要研究，架空设定也可以由作者直接约定，题材名称不自动触发联网。

研究完成后读取与问题相关的发现和来源，核对时代、地区与适用条件，必要部分写入世界 YAML；应用建议保持候选。重要来源相互冲突时保留分歧，回到具体决定处理。已有材料未变且问题已解决时继续设计。

## 交付

写入 `pipeline/phase1_world.yaml`；只有实际开展研究才保留相应报告。Phase 2 据此建立人物生活和经历，Phase 4–6 据此判断事件条件及表达。交付前核对关键规则能否解释预期后果、不同规则是否相容、未知项和人物误解是否被误当事实。发现缺口时补对应条件，避免重建无关设定。
