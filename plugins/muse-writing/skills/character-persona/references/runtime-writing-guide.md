# runtime 模式填写指南

本 skill 的填写启发。`phase2_character.yaml` 保留完整作者设计；runtime SKILL 只接收角色在故事入口可用于感知、判断和行动的信息。构建器完成语义编译，不把作者诊断换个标题原样搬运。

## 身份与处境：不突出职业标签

> 「身份标签是调味料，不是主菜。角色的职业偶尔影响语言，但不应成为默认修辞模式。程序员在求生时首先是人，其次才是程序员。」

| 避免 | 推荐 |
|------|------|
| 陈默，30岁，资深后端工程师 | 陈默，30岁，写了八年代码的人，最近开始怀疑自己是不是只会跟机器说话 |
| 黎安，29岁，战地医护兵 | 黎安，29岁，在沙漠哨站撑着临时病房，别人发烧流血时第一反应总是找她 |

## 经历与信念：只给角色真正拥有的材料

把 backstory 写成角色经历过或相信的事件及其当前影响。`narrative_use`、隐藏真相和作者计划留在 Phase 2。

| 避免 | 推荐 |
|------|------|
| “童年失火将在第三幕解释她的背叛” | “她记得母亲先抢出账本，后来才回头找她；她至今把保存证据看得比求救可靠” |
| 把客观世界设定全部塞给角色 | 只写她亲历、听闻或已经接受的那部分世界 |

## 自觉追求：写角色能够承认的目标

自觉追求应当具体到角色知道自己正在争取、保护、回避或完成什么。`不自觉欲望` 留在作者侧，通过下一节的行为倾向产生作用。

## 判断习惯与行为盲区：把诊断变成可表演倾向

Phase 2 的 `unconscious / core_flaw / characterization_vs_truth` 可以帮助构建器理解人物，runtime 只保留当前已经成立的注意、归因、误判、选择或回避方式。

| 避免 | 推荐 |
|------|------|
| “她的核心缺陷是把控制误作照顾” | “别人拒绝她的安排时，她先假定对方没看清危险，往往继续替对方决定，很少先问对方想要什么” |
| “她其实渴望被承认” | “功劳被略过时，她会补充过程和证据，却坚持说自己只在纠正记录” |
| “压力会揭示她外冷内热的性格真相” | “面对陌生人的求助，她先核对资源；确认能承担后才动手，也不解释自己的迟疑” |

行为盲区仍是人物的盲区。不要把它改写成角色对自己的准确心理报告，也不要借此预告弧光终点。

## 声音框架：定义倾向，不定义映射

> 「不要过分铺陈，像撒胡椒面一样地在稿纸上加上没完没了的有关行为、手势、语调方面的描写。」
> —— 麦基《故事》第十七章

| 避免 | 推荐 |
|------|------|
| rhetoric: "心跳加速=CPU负载红线" | "排查设备故障时会使用准确术语；普通恐惧仍按当时感官与行动表达" |
| syntax: "短句、动词主导；情感涌动时句子变长、变碎" | "来源显示她在正式作证时按时间完整陈述，面对某人追问时常省去关键主语" |
| 全文为角色设计大量情感→修辞映射 | 描述有来源、会影响当前故事的倾向，Phase 6 按刺激、对象与目的决定具体句法 |

## 边界：保持可归因

边界定义角色在有来源条件下受到什么限制。它需要回指 Phase 2 的 voice_boundaries、经历、价值锚或明确关系条件，保留时间、对象与强度；倾向和当前承诺不升级为绝对禁令，已成立的强底线继续保持。没有来源时不为形成完整外观而新增禁令：

| 角色 | 正面描述（有用但不够） | 边界（更有效） |
|------|---------------------|---------------|
| 沉默寡言的军人 | "说话简洁有力" | "体力透支且面对陌生人时,不会长篇分析自己的感受;正式作证时可以完整陈述" |
| 温柔的老师 | "说话温和耐心" | "教室纠错时不用居高临下的口气;遇到伤害学生的行为时允许直接斥责" |

## 作者侧字段怎样进入 runtime

表里一致时，编译已成立的判断习惯与坚持；“判断习惯与行为盲区”章节可只写前者，不据标题补造盲区或隐藏动机。

- `inner_capacity` 继续留在 Phase 2。角色已经形成的自我维持习惯可按其主观意义并入“经历与信念”或“判断习惯与行为盲区”；`why_load_bearing / loss_trigger / loss_signal` 不复制。
- `subjectivity_object` 的当前物件事实只在角色知道且会影响当下行为时并入“经历与信念”或“边界”；`potential_use` 不复制。
- `character_arc` 的终点与轨迹由作者侧阶段消费。`start_state` 只用于初始化 state.md，不进入静态 SKILL 或 adapter。
- 通用表演方法由 `character-actor` 维护，各角色包只保留角色特有的信息。

## 对手和配角的简化版

以下是常见的深度梯度，但不是硬规则——根据角色在故事中的实际分量决定：

| 角色类型 | SKILL.md 参考深度 | state.md 参考深度 |
|---------|------------------|------------------|
| 主角 | 六类 actor-facing 信息均写实 | 完整初始化 |
| 对手 | 六类 actor-facing 信息均从对手本人视角写实 | 完整初始化 |
| 有独立对白的配角 | 各必备章节保持简洁，只写对本故事承重的内容 | 至少需要关系感知与已知信息 |
| 纯背景角色 | 通常不需要独立 Skill | — |
