# 从人物依据生成候选

## 当前输入

先读本人 role_view，取得 `known_now / observable_stimuli / constraints_now`。本人 runtime package 与 state 只补充本时点成立的经历、声音和主观状态；state 的记录时点不一定是当前场次。冲突无法解释时回派生者。作者诊断、弧光终点和他人私密目标留在作者侧。

只读取本次选中的角色专属 dialogue ref；MATCH 的事件用于理解在什么关系、压力与共享知识下形成该回应。单一有据来源也可适用，来源数量不决定可迁移性。参考中的人物事实不覆盖本角色依据。缺参考或 NO_MATCH 时按现有人物材料继续。

完整 scene_card、其他角色 view、全局设计和其他场景原文由派生者处理，actor 从自己的 view 获得当前事实。

## 内部推演

让这个人的经历、信念与盲区决定他如何解释现场，再从实际选择与代价产生言语、身体或心理行动：

```text
已有前提 → 当前刺激或主动追求的含义 → 选择 → 希望造成的即时变化
```

误判可以成立，自知与信息来源须成立。坦白、安抚、拒绝、合作、威胁、沉默或离开均由人物处境决定，不预设情绪强度和句长。主动发起可来自已有承诺，无需虚构新刺激。

《对白》第二章“动作”区分心理、身体与言语行动。心理行动使态度、信念、预期或理解发生变化，可以留在内心。人物对反证的解释、自我质疑和有限修正会改变本场写法时，可形成候选；一般内心叙述继续交 writer，人物无需把思考说出口。

`meaning` 保留既有经历或信念怎样影响当前理解；`move` 写人物实际可能作出的核对、选择或有限修正；`intended_effect` 表达其原本希望促成的作用。期望与实际认识可以不同，候选只保留本时点已经成立的变化。

多个 cue 促成同一选择时合为一个 move。人物独有的经历或关系实际改变了解释、注意或回应方式时保留候选；普通程序与无信息增量的表情无需另列。候选稀疏指减少无用复述，不要求人物每次都作出异于常人的动作。

## 落盘前判断

按[输出契约](output-schema.md)检查角色身份、可选 on 引用和字段类型。每个 meaning 只留理解候选所需的简短依据；move 是人物可实施的言语、身体或心理行动，intended_effect 属于其当下希望促成的作用。删除会损伤人物目的、接收者理解、关系或声线的内容应保留。

可定位问题原位修复；无有用候选写空 moves。完整推导与规则说明不进入产物。
