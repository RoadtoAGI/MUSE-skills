## 输入

`scope=scenes` 是 Phase 6 默认审查；`scope=manuscript` 是 Phase 7 装配后的全稿语义审查。两种 scope 共用本文件的病理机制与非触发边界，读取的正文源不同：

- `scope=scenes`：`pipeline/scenes/scene_{id}.md` — 全部场景正文（核心依赖）
- `scope=manuscript`：dispatch 指定的 `pipeline/review/snapshots/story.semantic.round{N}.md` — 本轮冻结全文（唯一正文输入）；不读实时 `story.md`、单场景正文、旧 A 报告、reader 报告或修订总结
- `scope=manuscript` 同时读取本轮 wholetext 报告的定位线索，核对其 input_story_sha256 对应受审快照；统计与模型判断分别解释。
- `pipeline/phase2_character.yaml` — 作者侧人物设计、经历与结构基准（核心依赖）
- `pipeline/story-character-skills/.claude/skills/{slug}/SKILL.md` — 稳定经历、信念、判断习惯、声音和边界（核心依赖）；`pipeline/characters/{角色名}.md` 仅作身份与声音兼容投影
- `pipeline/phase5_scenes.yaml` — 按受审场景读取对应条目的作用、必要结果、边界与 handoff；已填写的 `omission_plan` 连同 `reader_track / scene_tasks` 核对，即使未填写 `craft_carrier` 也适用
- 按实际疑点读取 `pipeline/phase0_conception.yaml` 的作者要求、风格与来源，Phase 1 世界、Phase 3 脊椎、Phase 4 结构及当前采用的 ledger/参考；这些材料解释约束与选择，不能代替正文实现。
- `pipeline/review/lint/{scene_id}.*.yaml` — **仅 `scope=scenes` 读取**的 L1 脚本 lint 报告合集（核心依赖，Step 5 Phase A 产出）
  - `{scene_id}.ai_filler.yaml`（S1：口癖 / Markdown / 排比 / 关联词）
  - `{scene_id}.lexical_stats.yaml`（S2：副词密度 / TTR / 感官平衡 / 高频词——统计型，读 `density.*.imbalanced/overuse/too_low` 布尔字段）
  - `{scene_id}.dialogue.yaml`（S3：纯台词 / 指代 / 说话动作孤立 / 模板说话动词）

**与 lint 分工**：lint 已定位具体位置的模式，A 组**先读 lint report 了解已定位位置**避免重复扫描；A 组工作是在此基础上做语义判读（是否命中病理机制 / 是否属于非触发边界）+ 覆盖脚本查不了的维度（即下方主表逐项）。

全稿 findings 只收可定位的语义错误或已说明阅读损害的问题；只有风格偏好时留作作者可选意见，不将其写成阻断 finding。正文未变而来源或分类确有错误时，可按主控指明的错误补正同轮报告，保留修正依据；无需改正文来换取通过。

### 1. AI 套路检测

→ 模式清单见 `prose-craft` skill 的 [`references/ai-cliche-patterns.md`](../../prose-craft/references/ai-cliche-patterns.md)
→ **承载模式参考**（合法名著手法判读时按需查）：[`prose-craft/references/novel-craft-patterns.md`](../../prose-craft/references/novel-craft-patterns.md)（A 类承载点 / B 类视角 / C 类高潮 / D 类人物 / E 类形态）

依据当前正文和定位线索选择相关机制（见 ai-cliche-patterns.md）；下列五类列出本组**额外的语义判读 / lint 联动信号**：

**A. 场景焦点类**（语义判，lint 不覆盖）— 主次失焦 / "描写→说话"强制收束

**B. 修辞类**
- 语义判（lint 不覆盖）：无功能修辞 / 格言金句 / 比喻堆砌
- **lint 定位后的语义处置**：observe 命中按当前作用判断，成立的问题写入现有 finding，不另造逐 hit 台账。代词、指示限定、连接词与名词复现按指称和承接作用判断，密度不构成删改预算。

**C. 情绪类**（语义判，lint 不覆盖）— 情绪压制公式（感受→微动作→压回→转任务）/ 情绪库存短语（"血液冰凉" / "心脏一缩"等）

**D. 说话描写类**
- 说话动作窄库——声音状态标签（"声音平静" / "低声道"）代替让对白本身传递情绪
- **lint 已定位**：`template_speech_verb`（"XX 地/的说道"模板，S3）；窄库其余词汇（"低吼 / 沉声道 / 压低声音"）留 A 组语义判

**E. 段落结构类** — 段落密度偏离范文。A 组**不现场运行脚本**：若 orchestrator 已产出 `pipeline/review/lint/{scene_id}.density_vs_ref.yaml`（Phase 6 执行协议 §3.5），读 output / reference / gap / verdict（SIGNIFICANT_DEVIATION）判"题材盲的均质分段"；否则跳过。**数据是参考非强制**：急促动作 / 情感收束即使 long_pct 差距大也不是问题；只在场景明显需要长景深（复杂对峙 / 空间展开 / 内心深化）却被切成均质中段落时才标记。

对每个命中：引用原文段落，说明命中了哪个模式，建议替代方向。

### 2. 角色声音一致性

> 「没有表达性的对白，事件就少了深度，角色丧失层次，故事也变得平板。」—— 《对白》前言

声音 finding 以成品对白和角色来源之间的可定位冲突为依据。runtime `SKILL.md` 的声音特征、行为边界与人物当前关系和压力共同构成参照；人物可以共享日常词汇、礼仪语域和程序文体，也可以因现场目的改变句长与合作姿态。

遮名与跨场景对比只提供候选信号。每个真问题引用成品中的具体对白,说明它与哪条角色来源或当前状态冲突,以及冲突怎样造成角色不可辨、关系姿态失真或压力反应失真。局部相似本身不构成 finding。

### 2b. 遮作者测试（成稿声音缺席诊断）

剥去情节信息，只看叙述判断、选词、句法取舍与细节偏向：正文应留下可指认的作者性选择。通篇均质中立、持续对冲、修到只剩无风险通顺句时，报告 `author_voice_absence`，并引用至少一处具体 span 说明缺席如何呈现。该 finding 只作审美诊断，不进入机器 blocking。

冷感、档案体或有意省略按成品作用判断，scene_card 声明可以补强；审美诊断供作者选择。

### 3. 场景价值变化

→ 诊断方法见 [`references/mckee-diagnostics.md`](mckee-diagnostics.md) § 场景分析法

结合本场在故事中的作用，对比进入与离开时的实际变化：欲望追求看价值、代价或可选行动，信息组织看认知与误读，母题或观察组织看关系、感知与意义如何累积。对照 Phase 5 的 `value_start/end`，引用成品说明实际增量；正负符号相同不能单独推出“无事件”。既无独立作用也无累积作用时，再建议删除或合并。

### 4. 对白的场内交流效果

→ 诊断方法见 [`references/mckee-diagnostics.md`](mckee-diagnostics.md) § 潜台词塌缩

对白应在场内对象之间传递信息、实施行动或改变关系。A 组从成品判断接收者能否恢复信息、上一轮是否影响下一轮、人物是否越过自知边界,再定位失效机制。

#### §4.A 自知与表达边界

以下表面形态只作为候选信号：

- 角色说出的感受或结论超出其当前自知;
- 主题阐释缺少人物在场内的说话目的;
- 人物准确命名了本应属于作者侧的不自觉欲望、核心缺陷、`end_state` 或轨迹机制。

坦白、报告、解释、请求、和解与直接攻击可以直说感受,完整长句也可以成立。finding 必须引用成品原文,说明人物不可能知道什么,或这句话为何没有对场内对象实施可观察作用。

#### §4.B 对白脱节（隐晦 / 演讲方向）

→ 详细规则见 [`dialogue-craft/references/dialogue-rules.md`](../../dialogue-craft/references/dialogue-rules.md) § 对白交流契约

A 组判断对白是否服务场内交流。以下四类是常见诊断候选,不构成封闭分类：

- 无场内理由的隐语 / 哑谜（无密语约定、无防偷听、无装腔铺垫）
- 对已知者重述已知信息（"as you know, Bob" 演讲式）
- 省略到接收者无法恢复指代（话语落空）
- 文学化玄言替代有效信息（双重含义堆叠 / 抒情对仗）

非触发条件：装腔、暗号、防偷听或自言自语具有场内动机与接收逻辑;正式汇报、教学、照护、坦白与低压合作也可使用直接或完整表达。

每个 finding 必须同时提供成品原文引文与可观察失效:接收者无法恢复指代、上一轮刺激没有影响本轮、关系行动消失、人物越过自知边界,或声音与可归因角色来源冲突。只有表面词形或技巧名称时不报告。

### 4b. 表述来源判读

reference、设计或 role move 表述进入正文，本身不构成 finding；只有与当前场景契约冲突或造成可独立定位的阅读问题时才报告。

**候选结构用词**（只在承担创作元话语或设计泄漏时报告，故事内同形词与授权原文可保留）：
`潜台词`、`价值转折`、`鸿沟`、`节拍`、`弧光`、`脊椎`、`主控思想`、`激励事件`、`进展纠葛`、`不归点`、`序列高潮`、`递进方向`、`冲击力`、`价值起点`、`价值终点`、`beat_direction`、`scene_tasks`、`handoff`

**需结合语境判读的句式**（正常判断、推理与叙述评论可以成立）：
- "他知道这意味着…" / "这道命令的潜台词是…" / "真正的意思是…" → 作者在替读者解读
- "这是一个不可逆转的选择" / "从此再也无法回头" → Phase 3 crisis 标注的直接显化
- "此处体现了…" / "这一刻象征着…" → 元叙述评论
- "根据…原理" / "按照…的逻辑" → 创作理论或设计文档语言

设计或 role move 原句只要贴切且阅读成立即可保留。对每个真命中：引用正文段落，说明它与当前场景契约的冲突或具体阅读损伤；可补充上游来源帮助修订，但来源本身不是定罪依据。

### 5. 可信性瑕疵

→ 诊断方法见 [`references/mckee-diagnostics.md`](mckee-diagnostics.md) § 可信性瑕疵

扫描：**空洞字眼**（表达缺少场内需要及人物、关系、声音或节奏作用）/ **过度滥情**（情绪强度缺少处境与人物依据）/ **过度感知**（角色自我分析越过当时知识与自知）/ **借口冒充动机**（既有行为与自我辩护之间的间距被无因抹平）。信息说明、直接表达与有效心理展开按上述条件判断。

### 6. 动作流水账 / 低读者收益段检测

**核心判断**：在相关句段与上下文中做删并判断：删去或合并后，读者是否损失必要理解、人物经验、关系、节奏或形式作用？危险、欲望、世界认识与情绪变化是开放例子，不是逐动作计数表。必要连接和体验积累可以保留；删后上述作用均不减少的重复动作链可收束。

**命中类型**：

- **低读者收益动作链**：连续动作不新增 plot / character / world rule / danger / turn / formal delight
- **物资 / 空间 / 流程盘点**：同构句式（item→check→pack / move→door→walk 等）连续呈现
- **角色特质误写成正文形态**：角色清单化思考在正文形成僵硬条目感，且没有新增读者收益
- **可删除的舞台指示**：动作句答"发生了什么"但不答"发生于谁 / 如何发生"

**处理方向**：

- 按实际损害选择删合、补明或重组；先保留必要理解与体验，再收束无作用的重复
- 动作过程承担具体的危险变化、人物选择或不可逆代价时保留承重部分；变化已经成立时直接给结果或省略
- 过渡动作同时核对空间连续、话轮归属与叙述节奏；这些作用均可恢复且确属重复时再删合

**句级细则**：

> 「优秀的写作不太强调发生了什么，而是强调发生于谁、为什么发生以及如何发生。」
> —— 分级节拍理论

扫描以下类型：

- **事件记录式动作句**——动作句只答"发生了什么"（转身、走、合上笔记本），不答"发生于谁"或"如何发生"；可集中也可分散（单独成段短动作句尤其易成流水账节奏）
- **设计动作形成逐项流水账**——只在规划内容进入正文后形成无读者收益的叙述清单时报告；逐字复用本身不是问题
- **可删除的舞台指示**——删掉某物理动作后读者对场景理解不减少 → 冗余
- **身份或形式伪装的流水账**——程序员、军人等职业身份，日志、清单、碎段或短切装置没有让具体压力、选择或读者判断发生变化时，仍按低收益动作链报告

对每个命中：引用相关句段，说明删并后理解与体验的具体变化。修订按具体问题删除、合并、补明或重排；空间连续性、话轮归属、因果、人物经验与节奏需要时保留原有过程或承接，不为具体化统一补动作。

### 7. 微观语言错配

→ 详细判据 / hot zone 加权 / reader-visible damage 判读流程 / 修订方向见 [`A_aesthetic-micro_language.md`](A_aesthetic-micro_language.md)

句级"看似有文气但不成立"问题。命中时 `dimension: micro_language`，并填 `subkind`（`false_literary_diction` / `sensory_mismatch` / `abstract_judgment_without_action` / `stock_speech_tag` / `weak_character_expression`）。

**只报影响阅读的句子**（reader-visible damage 原则）；每条 finding 必须给 `evidence_quote` 原句和一句失败原因。

### 8. 感官与场景需要

S2 的 sensory_balance 只显示词面分布。按人物可感范围、叙述距离与本段作用判断是否真有信息或体验缺口；视觉占比、题材和时间环境不能推出必须补触觉/嗅觉。已有准确视觉叙述足够时保留。

确有缺口时引用位置，说明读者缺少什么、怎样影响理解或体验，再建议适合当前处境的材料。声音、触感、气味也须有具体作用，不为感官配额补细节。

### 9. 视角边界（焦点角色感知越界）

> 与 B 组 §3.A（**跨场景**视角切换规则）分工——A 组专注**单场景内**焦点角色感知边界。

**扫描方法**：从设计与正文确认当前叙述方式及必要知识边界。贴身 POV 下，下列形态只提供候选；全知叙述者可按作品约定交代人物未知信息：

- `[其他角色名]想 / 知道 / 感到 / 意识到 / 在心里 / 暗暗 ...` —— 焦点角色不可能知道他人心理
- `[其他角色名]紧握的手出了汗 / 心跳加速 ...` —— 生理指标焦点角色不可能察觉
- 超出焦点角色感官范围的环境细节（焦点在室内却描述室外具体动作）

**排除项**（不是越界）：焦点角色**推测**他人心理（"他看起来在生气" / "她大概是在想…"）/ 自由间接话语（free indirect discourse）有意设计 / 不可靠叙述者有意设计。

对每个命中：引用原文，说明焦点角色为何不可能知道这条信息。（当前 A 组全手工扫描）

同时核对本场已明确的读者披露条件：按受审正文的呈现顺序，比较 `reader_track / scene_tasks / omission_plan` 与读者实际取得的事实和确认。当前必要理解应有正文依据；有疑点时回查 Phase 3 `reader_spine` 的全篇意图。提前确认受保护答案，沿已有 `dimension: ai_pattern / subkind: omission_violated` 报告，引用正文和仍生效的保留条件；人物越过所知范围则沿 `pov_boundary` 等既有维度判断。A 组读取设计属于作者侧核对，不改变 reader 的盲读输入。

读者先知而人物后知可以形成戏剧反讽，先告结果也可使后文追踪原因和代价；依当前有效设计判断。字段缺省本身不构成问题，正文形成了合法的新承载或在约定条件满足后确认答案时保留。

### 10. 场景收尾

结合本场的变化、后续衔接与全篇节奏读末段。收尾可用对白、判断、动作、感官、余波或悬而未决的问题；具体形态不决定优劣。

只有末段重复刚成立的意义、人物无场内目的地替作者点题、破坏既定信息保留，或连续套用同一形式使本场作用钝化时，引用原文报告。必要的直接认识、哲理表达和闭合结局可以保留。建议针对实际冗余或断裂，不要求统一换成小动作、停格或开放问题。
