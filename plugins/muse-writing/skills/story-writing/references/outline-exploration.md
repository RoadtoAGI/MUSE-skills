# 大纲构思与回读

当前阶段的设计负责人负责把参考变成新的剧情可能，比较、补强并提出推荐，作者负责审美选择与采纳。本协议供长链构想与 Phase 1–5、短链构想与大纲共用，在关键构思尚未确定、参考可能改变设计，或作者退回方案时使用。已进入当前上下文的指导、来源与裁决直接复用；材料缺失或变化时补读受影响部分。已经认可的方向继续展开；局部补足设定、校正事实和格式不另开候选轮。

```text
[当前需要解决的构思问题]
              |
              v
[故事理论 + 名著拆解与原文]
              |
              v
[发现新的认识，迁入本作关系]
              |
              v
[不同构思 + 关键剧情推演]
              |
              v
     [候选评价、补强与推荐]
              |
              v
         [作者裁决]
          /       \
       采用       退回
        |          |
        v          v
[写入既有大纲] [定位思想、迁移或剧情问题]
        |          |
        v          v
[向后续交接]   [定向回读，重构候选]
                   |
                   +--> 回到候选评价与推荐
```

## 确定开放问题

以原始需求、作者当前裁决与本阶段的有效设计为依据。作者明确的关系、人物立场、固定结局和参考用途构成当前边界；发现上游模型解释与其冲突时，回到对应决定修正。

围绕具体难题构思：这套世界规则让谁以什么方式生活；某人的善意为何会产生意外后果；哪项新事实会改变已建立的关系；同一事物怎样使读者重新理解前面的行为。理论选用本阶段已有麦基参考中相关的冲突、人物、因果、价值或信息组织知识，帮助推演问题；需要调研时再把难题写入请求。

模型主动从参考和本作条件中提出尚未被需求说出的观察。对人的理解、社会关系或世界认识发生了什么变化，要能用具体关系说明。新的主题解释作为候选提出，采用前保留作者已经确定的含义。固定结局、人物设计或观察性作品围绕其开放部分发散。

作者尚未确定作品含义时，共同人物设定应保留主题的探索空间。会规定故事答案的性格缺陷、关系病因和人生判断放在各自候选中，避免一次人物定性提前收窄全部方向。参考带来的观察与人物、事件推演可以交替深化。

## 带着问题理解名著

已有材料能回答当前问题时直接使用；缺少思想或情节依据时，通过宿主可用方式加载 `design-doc-reference` 补取，传入当前 `phase`、可用 `signals`、参考偏好，以及自由文本 `narrative_problem`。核心认识与前提尚未定型时用 phase=0；短链按当前设计问题选择相应长链尺度，脊椎问题用 phase=3，场景组织问题用 phase=5；这些参数用于取材，不改变本作阶段编号或产物路径。

`narrative_problem` 说明已经确定什么、尚缺什么认识或剧情关系，以及本轮反馈指出的偏差。请求参考回答原作怎样形成相关认识、哪些事件与条件使它成立、本作可以从中发展什么。题材信息帮助理解语境；思想或叙事功能相通时，请求扩展到其他题材。作者明确的来源绑定继续有效。

新增材料以本次成功返回为准，失败或零结果时保留该请求未解决的问题。可用的既有来源继续复用，沿用其出处记录；文件存在性不能冒充本轮新查询成功。参考受限时可继续按现有事实和理论提出构思，遵守作者的来源要求。

读懂参考的三个相连部分：

- 原作让人看到什么具体认识，哪些人物、行为、制度或物件之间的关系承载它。
- 这种认识如何在事件中形成：读者先知道什么，人物怎样理解与行动，后果又如何改变原来的判断。
- 它依赖什么语境，迁到本作之后，人物的利益、知情条件、行动含义和结果会怎样变化。

摘要只有主题标签、机制名称或结论，无法解释成立过程时，沿来源请求回读相关原文及必要上下文。原文已在本 run 内可用时直接读取；跨包来源由参考 skill 取得可消费材料。反馈也可以触发回读。阅读范围由要理解的关系决定，可跨场、跨章并比较多部作品，不设作品数、卡片数或回读次数配额。

原作事实、对原作的解释与本作新构思在说明中各有归属。无法定位的原作细节不当作事实引用。解释全文象征或作者思想时，以实际读到的文本为依据。

## 迁移并展开剧情

先在本作中尝试这项认识：它会改变谁与谁的关系，产生怎样的愿望、误解、行动或世界后果。模型需要贡献需求尚未给出的新联系；转述作者命题、替换名词和增大灾难规模不足以显示这项贡献。

人物已有的长处、职业能力和生活秩序本身也能产生值得写的问题。观察同一种能力在不同人、场合与时间中实际起了什么作用，让帮助、依赖、误解或其他关系从具体经历中显现。把一项能力解释成待克服的缺陷，是一种候选判断；其成立需要本作事件支持。

围绕真正未决的选择给出多个有实质差异的构思，数量随创作空间与作者反馈变化。区别可以来自观察角度、人物关系、世界运行方式、因果起点或读者理解路径。用自然叙述让作者理解以下内容，篇幅与组织随任务决定：

- **具体故事**：发生什么，人物如何行动，局面因而如何改变。
- **思想与来源**：它提出了什么新观察，参考启发了哪项关系，本作作了怎样的改造。
- **关键剧情推演**：选取决定该构思能否成立的事件，交代先前条件、人物当时的理解、行动及下一步后果；说明读者可能在哪里期待、误解、惊讶或重新理解。

在构思中推演关键事件及后果，篇幅以作者理解方案所需为准。由人物的知识、欲望与盲区作选择；关键解法沿用已建立的条件。选择互斥时交代具体条件，可以兼做、延后或通过合作实现的行为继续保留。世界规则、因果与隐喻关系落实在剧情中；含糊处补必要解释。

暗喻随故事需要使用。采用时，让表层事物的性质及其参与的行动承载深层关系，观察它在不同情境中能否继续产生有意义的后果。对应表、主题标签和结尾解释不单独证明暗喻成立。喜剧、观察、静态人物、任务和重复叙事按各自的阅读效果推演，不额外配给牺牲、惩罚或两难。

## 评价、推荐与作者反馈

提交前修正违背已知事实、遗漏关键因果或改变作者明确含义的部分。围绕本轮期望的阅读效果比较具体候选，说明推荐方向、成立条件和取舍；保留有实质差异、值得作者判断的探索方向。推荐理由落到人物、事件和读者理解的变化；新鲜感、情感张力等判断按本作目标使用，不给所有作品套用固定审美总分。作者可以选取、组合、局部认可或全部退回，材料检索的相关性排序只决定先读什么。

形成需要比较的候选、准备推荐或重做被退回的构思时，使用本作品 `<work_dir>/.muse/runtime.yaml` 的现有模式，无文件为 `standard`。`jev` 模式下先执行 `python3 -m muse_runtime brainstorm guide`，读取当前运行包提供的调用协议，再执行 `python3 -m muse_runtime brainstorm evaluate --work-dir <work_dir> --input <round.json>`。输入包含作者原始目标、已确认约束、相关事实与反馈、各候选的具体故事及关键推演。临时 JSON 只承担调用传输，候选与反馈继续保存在已有设计参考或共创记录中；不新建采纳台账。共同接口与结果解释以该指南为准，已读且未变化时直接复用。

Jev 的推荐和逐候选判断供当前设计负责人决定补取参考、补推事件、重构或提交作者；解释须回到候选内容与来源。全部候选需要重做时，沿下表定位最早失真的决定；信息不足时先补取已有材料，真正涉及作者偏好或保留方向的分歧再交作者。低评价本身不删去有潜力的独特方向，评价通过也不写成作者认可。`standard` 模式沿本协议直接共创，无需安装运行包；启用 Jev 后遇到缺依赖或调用失败，明确本轮尚未完成 Jev 评价，继续已有创作流程。作者明确要求先取得 Jev 判断时，报告缺件并继续不依赖该判断的工作。调用失败不转成新的大纲审批状态。

沿用当前共创对话和已有大纲闸，不新增审批状态。尚未裁决且后续设计依赖某个方向时，先提交可判断的候选，等待选择。作者已经认可的内容直接继承；明确授权免审或直接完成时按原有授权继续，形成工作方案并保留模型选择与作者认可的区别，`waived` 保持原有含义。

收到退回后，结合反馈和实际产物定位首次需要重做的决定：

| 反馈与证据 | 下一步 |
|---|---|
| 没有新认识，候选换皮，或含义偏离原意 | 回到思想问题与原作关系，寻找能改变构思的新观察 |
| 原作关系在新语境中变了意义 | 回读原作成立条件，重新推演本作人物的利益、信息与行为后果 |
| 有想法，关键行动或转折不成立 | 回读相关情节推进，重做影响结果的条件与选择 |
| 局部被认可，其余部分仍平庸 | 保留认可内容，沿未决部分继续取材与发散 |
| 大纲保有吸引力，正文或角色交接丢失它 | 对照实际下游输入，交给首次偏移处的负责人修订 |

反馈笼统时，模型先提出有依据的诊断与具体改法，确需澄清再问影响方向的问题。保留作者局部认可的关系、情节或表达，把否决理由用于本轮未决部分的取材、提问与重新生成；一次反馈只在其适用范围生效。用新的候选呈现创作变化；改变作者已认可内容时说明影响。需要新理解而原材料无法提供时，再换来源、比较关系或重新提问。输入未实质变化时复用已有评价；重新评价以目标、候选或反馈发生实际变化为依据。

## 写入与交接

候选与回读结论留在既有设计参考或当前共创记录中，不为每轮新建表单。选定后把必要信息写入现有产物：

| 产物 | 保留内容 |
|---|---|
| 当前 phase YAML / 短链 outline | 选定的具体关系、世界规则作用、关键因果、人物选择及读者理解路径，按各自现有字段表达 |
| 长链 `inspiration_ledger.yaml` | 既有 `source / abstraction / project_encoding[].design_value` 记录来源、所学认识与本作作用，遵守原有 accepted/bound 及引用契约 |
| 短链 `inspiration_ledger.yaml` | 既有 `source / project_encoding` 写清来源关系与本作化用，采用项标 adopted；保持现有字段结构 |
| 下一阶段实际输入 | 把本构思有吸引力的关系及其成立条件落实到相应结构或场景字段，保留作者指定的信息边界 |

台账采纳状态用于追踪材料消费，不能据此宣布作者认为精彩。只写与本阶段及后续创作有关的决定；人物表演、句子和可替换的微观动作留给创作者。需要更改前提或已认可的上游决定时，先把具体变化交回当前共创对话，再更新受影响产物。
