# 连续性检查

本技能判断当前章与既有事实、设计承诺是否相容。正文实现由 writer / reviser 负责；台账勘误交原记录负责人，涉及改变已确认事实时由用户裁决。已发布正文保留。

## 取得合时的对照材料

调用须提供包根、作品根 `series_root`、章工作区 `work_dir` 与 `chapter_id`。首次检查按 `phase5_scenes.yaml` 的阅读顺序读取已有场景正文及场景卡；章级修订后的检查读取本次修订的 `draft.md`，明确它与场景文件的版本关系。

先读章卡、当前卷纲条目及本章 `serial_context.md`，据正文涉及的事实定位对照源：

- 人物身份、关系、经历与能力：合时 persona、快照继承链、biography 及必要原文。退场条目与 `last_seen` 是定位线索；离开、死亡、倒叙和重新归来分别判断，最近记录章不能证明此后未出场。
- 世界事实：装配窗口内的原台账及有效前章 buffer 候选。最新 `facts_current` 适用于当前续写；历史场景按[上下文协议](../serial-chapter-writing/references/context-contract.md)回查发生时点与角色获知渠道。
- 已确认的世界边界、揭示计划和章末作用：读取相关 worldbook 分册、`world_reveal_plan` 与章卡。作者侧看见某条秘密，不意味着人物已知或正文已获准揭示。

资料缺失先回装配、编排或来源负责人。只报告影响当前判断的输入缺口；尚未取得决定性证据时，不给该项通过结论。

## 判断冲突

每个问题需要正文锚句、对照源及冲突成立的条件。重点判断：

| 对象 | 成立条件 | 合法用法 |
|---|---|---|
| 事实与能力 | 本场时点、实体和条件相同，正文却违背已确立的状态或能力限制 | 已交代的状态变化、限制不适用、人物误解或谎言不等于叙述事实冲突 |
| 人物出场与知识 | 按实际时间和获知渠道，人物无法在此出现或取得该信息 | 倒叙中的死者、离开后归来、场内听到他人告知均可成立 |
| 新设定 | 新增内容改变冻结边界、既定因果或作者保留的决定，且无授权依据 | 服务当前表达的普通器物、局部生活细节可由 writer 创作；台账未登记本身不能证明越界 |
| 揭示时点 | 正文实质公开了明确保留到后续的核心信息 | 伏笔暗示、角色猜测与读者确认分开；缺 `planned_at` 时查原意，不能直接推定禁令 |
| 章末作用 | 已确认的 hook 作用在实际章末失效，影响承接 | 观察完整收束段；平静结束、情绪余波或较早设置的未决问题可承担追读作用，无固定末三行要求 |

节奏密度、场景长短和对话比例只作为有出处的建议。审美取舍交用户，明确的事实冲突与硬性不符由本技能指出。

## 沿既有报告交接

返回 `review_findings`，字段沿[审稿格式](../consistency-review/references/output-schema.md)，不另造补丁或检查报告。orchestrator 将本次结果合入 `pipeline/review/B_narrative_consistency.yaml`：

- `subkind: serial_continuity` 标识本检查负责的条目；`dimension` 使用已有维度，`source` 仍为 `story | pipeline`。
- 可在场景修复的问题填写实际 `scene_id`，双方证据放 `evidence_quote / contradiction_pair`；`suggestion` 写修复方向和责任环节。
- 已证实且必须处理的系列设计或全局事实冲突写 scene_id: null、severity: CRITICAL，交已有 global_findings 路由；当前无法补齐的必要输入单独返回 required_input_gaps，由 orchestrator 回源，不能写成零问题通过。
- 语义等价的既有 B finding 合并保留来源，避免同一问题重复修订。本次复核替换该检查的受影响条目，保留其他检查结果并更新计数。

scene-review 使用这些证据给出既有四档裁决，只有它产生 `source=scene_review` 的补丁。修订后复核受到改动影响的连续性结论，交同一次 post-review 消费。若问题来自装配遗漏、错误摘要或上游设计，修复该来源并刷新实际受影响输入；仅换正文措辞不能关闭仍成立的冲突。
