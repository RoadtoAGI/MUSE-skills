# 校验指南

按调用范围核对真正相互依赖的断言。以下是逻辑与本包接口的判断方法；表格、绝对年份和固定检查顺序均按是否有助于当前判断选用。

## 时间与因果

从相关设计、正文及人物经历中提取事件、时间基准和精度。来源只给相对先后时保留相对关系；给出范围时使用范围，不取中点制造确定日期。年龄必须区分实际年龄、表观年龄及叙述者估计，跨身份、复活或穿越等情形按本作已确立的机制解释。

核对事件的先决条件是否在当时具备：人物真实出生与经历、机构成立与活动、技术出现与使用、消息发出与接收。先查适用条件，再做算术。时间先后与因果关系只有在设计确立了依赖时才绑定；场景按读者呈现顺序排列，倒叙、插叙和并行线可以改变其时间顺序。

| 材料与情况 | 判断及理由 |
|---|---|
| 2040 年角色确为 30 岁，2015 年已满 18 岁入职；无改变年龄的机制 | 两断言无法共存：2015 年最多约 6 岁。报告字段与推导，交人物经历来源修复 |
| 2040 年角色“看起来 30 岁”，2015 年成年入职 | 表观年龄不确定出生年，不能据此报告矛盾 |
| S01 在冬天，S02 回忆同年夏天；来源已说明是倒叙 | 阅读顺序成立；继续核对夏天时角色可知的信息，保留倒叙 |
| 技术 2010 年已出现，2020 年合法化，2018 年有人非法使用 | 使用与合法化时间可共存；只有“2018 年合法使用”才需要对照法定条件 |

同一组数字换成另一人物或时期仍按相同逻辑判断，不能凭示例替作品新增跨时机制。尚不清楚某日期是事实、传闻还是规划时，记录所缺来源，不先要求作者修改设计。

## 世界与设计约束

从当前适用的 story_bible frozen、世界册、明确决定及有来源的事实中，找出约束的对象、条件和例外。对于某个计划结果，核对其依赖的能力、资源、空间距离、制度权限及获知渠道是否可成立。

- “本世界没有超光速技术”与无其他机制的超光速航程冲突；“尚未公开超光速技术”允许秘密研究，二者不能混读。
- “社会风气保守”描述总体倾向，激进人物可以存在；个人惯用方式也不等于永不改变的能力边界。
- 作者确定的卷末结果是设计义务。候选物件、动作、台词和表达形式由执行者选择；替换候选但保持必要因果与结果，不构成设计违反。
- 未发生的 tentpole、计划揭示和弧光终点不得写成角色已经经历或知道的事实。计划能否兑现与当前人物知情分别核对。

作者方向内部冲突时，在现有约束类别下列出冲突的具体要求，建议 serial-outline 提交作者裁决。驱动标签不同、角色保持稳定或主题由主角表达本身都不足以形成 finding。

## 引用与消费范围

按现有 [workspace-schema](../../serial-outline/references/workspace-schema.md) 与 [场景 schema](../../chapter-scene-plan/references/output-schema.md) 核实接口，名称显示和稳定标识分别处理。

| 对象 | 如何核对 |
|---|---|
| 角色 | 使用台账目录 char_id、persona 的明确姓名及已有 build-meta 映射。一次性功能角色可由本场明确身份和稳定 participant ID 建立；不要求先建长期角色包 |
| 章、单元、卷 | 裸章号和卷归属查当前卷纲及发布册；发布序取 published_seq，不把 ID 大小当时间。未定位规划允许 schema 定义的 unresolved |
| 场景 | scene_id 章内唯一并符合 `^S\d{2}$`；participants、POV 与场景定义对应。修 ID 时通知编排者同步受影响引用和路径，保护已有正文 |
| 序列、转折 | 只核对当前设计已经声明的关联及本范围应兑现的结果。单章无需承载整卷全部转折，跨卷未兑现线与未来规划按其范围保留 |
| 世界册与揭示 | 所引册、from_ceiling 和 reveal_id 能回到实际定义。区分已发生的事实、预期揭示时点与未决定的内容 |

候选名存在但与已有角色同名、某 alias 可指向两人，属于需要明确绑定的输入缺口。已明确要求的引用指向不存在对象，则属于 `reference_integrity`。只有名字看似不同、来源未确立异同，不能自动认定新人物或重命名。

### 本次采用的灵感卡

当前设计有 INS-* 引用时，读取其对应 `pipeline/inspiration_ledger.yaml` 条目与必要来源；无人采用的候选不要求例行整库审计。ledger 位于系列根时，可沿章内已物化链接读取；按实际来源文件解析相对位置。

- 当前引用的 ID 在 ledger 内唯一，状态为 accepted 或 bound，且类型与用途一致。phase5 的 pattern 引用与 `project_encoding` 关联按 [场景引用契约](../../chapter-scene-plan/references/output-schema.md) 核对。场景号仅章内唯一，跨章关联含混时回交当前设计负责人定位，不能借另一章同号场景确认。
- 来源用 canon 的 work/kb_id 或 web/direct 的 prototype_id/locators 定位。旧卡缺 kind 但含 kb_id 时按 canon 解释。web/direct 指向本 run 的 prototype_card 时，只核对该 card 的 sources 和当前使用条目。`verified_by` 记录来源工作由谁执行，其文字本身不证明事实真实性；内容疑点回来源技能。
- 本次复用的 reuse_candidates/allowed_quotes 保留实际来源锚与授权范围。候选卡的存在不等于作者已采纳，也不新增原文复用权限。
- disclosure_ladder 若用于当前场景，核对该层的内容、已发生铺垫和当前披露边界。层数、必须有物件及必须附禁说句都不构成普遍的一致性要求。

卡片的研究、生成、采用与撤回由当前设计负责人和 [inspiration-research](../../inspiration-research/SKILL.md) 承担。来源、目标或授权缺失而影响本次采用时，指明应补的输入；无需为报告复制整张卡或创建另一份台账。
