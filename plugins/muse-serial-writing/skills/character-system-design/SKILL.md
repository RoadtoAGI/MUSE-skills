# 连载人物系统

本技能把人物处境、追求和关系组织成后续卷纲与章内创作可用的依据。人物设计与情境相互约束：压力使选择付出代价，选择揭示人物如何看待自己、他人与目标。理论条件见 [麦基人物依据](references/mckee-character.md)。

## 输入与已有资料

先取得本次系列目录、要处理的人物及工作范围。读取 `story_bible` 中已确认的前提、价值与创作锚，`genre_profile` 和与人物有关的 worldbook 册；预置 `phase0_conception.yaml`、`phase1_world.yaml` 只在包含所需设计时使用。

已有角色先读合时的 persona、快照链、传记和必要正文，已有开工设计按需补读。确认人物 ID 与显示名，继承原文确立的身份、关系、能力和声音；补充只影响本次需要的缺口。接管已有基线时不补造开工 Phase 2 或 V00，人物后期经历也不回填早期 persona。来源时间与认知归属遵循 [上下文协议](../serial-chapter-writing/references/context-contract.md)。

设计遇到具体缺口时，通过宿主正式入口加载已可用的 `design-doc-reference`，传 `phase=2`、类型及人物追求/关系/表达问题，读取返回的实际参考。无可用依赖、匹配材料或知识库时，使用本包依据继续设计；已有足够参考直接复用。参考能改变当前人物判断才加载，不按角色数凑名著档案。保留机制、迁移条件和实际来源；采用人物、设定、情节或措辞的范围由当前创作约定决定。

## 形成可用的人物设计

按本次人物缺口完成以下判断，在同一份设计中表达相互关系，无需逐项生成独立报告。

| 决策 | 要留下的信息与判据 |
|---|---|
| 身份与处境 | 年龄、职业、社会位置、日常生活与实际限制。职业影响知识和利益，语言仍取决于经历、对象与当下目的。 |
| 欲望与选择 | 人物知道自己正在争取、保护或回避什么，为什么值得付出代价；存在内在冲突时再写不自觉欲望与缺陷。这一不自觉欲望须与自觉追求形成实际冲突，可具有破坏性；与自觉追求一致的经验动机保留为普通人物依据，不另造深层需要。 |
| 人物深度 | 外在形象、别人对他的判断，与受压选择之间有何对照；保留经历、关系及代价如何造成这种差异。表里一致的人可以在相冲突的责任、不同关系或极端代价中显出深度。 |
| 人物轨迹 | 写清本次规划区间内会变化、被揭示或保持的东西；模式字段见输出 schema。未来终点属于作者计划，不能变成角色已经知道的命运。 |
| 幕后经历 | 只保留影响当前追求、信念、关系或可能被叙事使用的过去事件；数量由用途决定，可暂留未知。作者设想的采收用途与已发生事件分开。 |
| 对抗力量 | 压力如何阻碍追求、改变代价与选择范围。可以来自具体人物、关系、制度、环境或内心；有人格的对手要有自己的利益与解释，但不要求每个对手都有正义感。 |
| 群像与关系 | 重要人物各自追求什么、掌握什么、对谁有权力或依赖；信任在什么事务上成立，双方是否有相同认识。配角深度与承担的场面相称；一次性功能人物只需本场成立的信息。 |
| 声音与表达 | 从真实经历、关系与沟通目标提炼能影响台词判断的倾向，保留适用条件。使用 [声音设计](references/voice-design.md) 补充确有缺口的方面。 |

复合主人公共同追求同一欲望并共同承担成败；多重主人公各有追求与利害，由各线关系形成整体。确定这种关系后再分配主角、双主角或群像职责，不按角色人数推定共同目标。

角色对照应能解释同一处境中不同的注意、风险判断或利益选择。例如两人都希望救人，一个有误救经历，另一个承担延误责任，他们可能选择不同的核实方式。差异来自经验与代价；无须把两人规定成每场都相反的“理性/感性”标签。

当前目标尚不足以解释办法选择时，读取[从追求到具体办法](references/mckee-character.md#从追求到具体办法)，补清人物同时顾惜什么、相信某种办法有效的经历及愿意承担的代价。相关依据进入已有欲望、经历、信念和关系文字；合时的自觉追求与信念供后续 `character_basis` 选取，作者诊断与未来变化保留在设计侧。

`inner_capacity` 只在某种信念或习惯实际支撑人物生活、且其受损会影响本故事时使用；`subjectivity_object` 只在具体物件承载该人物生活或关系时使用。误读、幕后故事采收和辨认路径也按实际情节需要选用。字段提供因果与候选实现，不能为凑完整度制造能力失灵、退场遗物、沉默或心理秘密。

## 设计与基线的归宿

完整字段和接收者见 [输出 schema](references/output-schema.md)。新作将作者侧开工设计写到 `series/character-skills/phase2_character.yaml`；此目录存在不表示已生成兼容包。后续补充人物的当前设计先在对应合时人物资料中表达，开工设计保留原来的时间含义。

对需要持续参与、被后续卷章读取的角色，建立 `series/ledgers/characters/<char_id>/`：

- `persona.md` 保留声音、追求、判断习惯及其经历依据。新作文件头含 `name` 和 `through_chapter: null`，正文只使用开场前成立的内容。
- `snapshots/V00.yaml` 是新作设计在开场的投影，记录当时状态、关系、能力与必要类型扩展；未来成长不进入快照。
- `biography.yaml` 使用既有模板，初始经历增量为空，后续由真实正文的转正流程追加。

文件结构、类型扩展和接管基线的截止字段以 [workspace-schema 的人物账本](../serial-outline/references/workspace-schema.md) 为准。已有人物资料保留，仅更新当前授权且受影响的设计；持续演化记录进快照与传记。

本包卷纲和章内创作通过合时人物台账与 role_view 获得人物输入。需要兼容外部角色接口、独立角色参考包或重建既有包时，才调用 [character-persona](../character-persona/SKILL.md)，给出明确人物集合、来源和时点；其结构校验只阻断该次包构建。一次性场景人物使用章内明确 ID 与身份，不为该次出场建立整套长期资产。

## 完成与反馈

交付时确认：主要人物的追求与阻碍可用于卷章设计；人物差异有处境依据；已发生与未来计划、客观事实与人物信念分开；当前需要的角色基线与 ID 可被装配器找到。缺少会改变身份、能力、关系或知识边界的来源，具体回交来源环节；人设和关系方向有实质分叉时交由 serial-outline 按既有人机权限处理。

设计足以支持当前规划便交接，不重复检查未变人物。角色表达与作品好坏仍由作者判断；字段齐备或包校验通过仅说明接口可用。
