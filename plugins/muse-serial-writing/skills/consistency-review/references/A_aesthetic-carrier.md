# 承载作用与作者意图

当正文被指为解释过多、反应不足、留白失效或设计承载缺失时，先核对这段文字实际要让读者取得什么。scene_card 中的 craft_carrier、omission_plan 和 narrator_distance 可以说明意图；未填字段的合法表达同样按正文判断。

- 原动作已传达同一意义，旁白只是复述，删后指称、承接、态度与节奏均成立：可报 `carrier_then_explain`。
- 旁白揭示了动作无法确定的信息，或其错误解读体现人物认知：检查是否符合叙述权限，不能只因“解释”删除。
- 作者明确要求隐去某项信息，正文却提前揭示：报 `omission_violated`，引用具体要求及揭示位置。
- 替换了承载物但保住必要因果、信息和作用：不报缺失；只有约束明确要求的对象或必要作用丢失时报告，并说明为何替代未成立。

例如，人物把信塞回抽屉，后接“他还没准备原谅她”可能提供动作本身不能确定的动机；前文已明确同一动机，该句又不承担回指、解释衔接或语气作用时，才有删除依据。保留与删除取决于信息关系，不由“动作后接心理”的表面结构决定。

承载物本身若是证物、后续事件条件或作者指定意象，按其实际约束保留。修复可以删、改或补；不把所有意义改成肢体动作。问题来源、引用与建议沿 [output-schema.md](output-schema.md)，正文实现与设计约束同一问题不在 A/C 重复立案。
