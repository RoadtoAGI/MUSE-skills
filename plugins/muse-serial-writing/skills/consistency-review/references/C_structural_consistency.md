# 时间、世界与设计约束（C 组）

读当前正文、本章 phase5/章卡、本卷相关条目、story_bible 和问题需要的世界分册/serial_context。作品根由 dispatch 提供；章目录内不要求额外生成小说 Phase 1–4。设计来源之间发生冲突时，交实际设计负责人；C 的对象是正文如何遵守有效约束。

| dimension | 核对内容 |
|---|---|
| timeline_plot | 事件的发生时点、时长、地点、因果与依赖是否可同时成立。插叙、倒叙、平行呈现按真实时间判断，不按阅读顺序判冲突 |
| world_building | 正文调用一条世界规则时，其必要条件及后果是否成立；规则不必每次用旁白解释，角色对规则的误认与世界事实分开 |
| pipeline_crosscheck | 作者事实、必要处境/结果、明确禁界是否在正文被破坏。候选动作、承载物和组织方法按其作用判断，不以字面复现为要求 |

人物作出新选择、拒绝候选动作、改变策略，可能正是事件的展开；涉及改写作者确定的事实或方向时回对应设计负责人。模型不能以“这样更好”为由取消作者约束。叙述距离变化只在越过有效叙述权限或破坏具体约定时报告。

本章已安排信息保留时，沿正文呈现顺序对照 phase5 的 `reader_track / scene_tasks / omission_plan` 与卷章相关意图，核对当前必要事实、延迟确认条件和实际分晓位置；世界规则继续按已有披露安排判断。提前确认受保护答案或省略必要依据时，引用正文与仍有效的条件，归现有 `pipeline_crosscheck`，与 A 组同处问题归并。人物所知按事件时点另核，读者先知、先果后因及有依据的误导按已选结构保留；无保密需要时不要求新增安排。

## 已采用来源机制

只检查本次场景实际绑定的 `inspiration_refs`，从 ledger 取得对应 accepted/bound 条目及采用范围。`project_encoding` 定位采用了什么；有 `disclosure_ladder` 时按该场的有效层判断信息如何呈现。分层揭示不适用于所有来源机制，候选及未绑定项不形成正文义务。

保留机制的决定性条件及作者明确要求的对象；可替换的 carrier 只核它承担的作用。找不到一个物件名不能证明机制缺失，旁白说明也不自动构成过度解释。缺少应有来源时回原采用环节，不能虚构来源或补写凑齐。

INS 问题仍使用既有 `pipeline_crosscheck` subkind：必要作用缺失用 `inspiration_bound_but_no_visible_carrier`，推断关系不成立用 `carrier_visible_but_inference_gap`，同义复述用 `carrier_overexplained`，已明确采用的人物机制未体现用 `archetype_declared_but_no_recognition_path`。这些名称用于定位，严重度由实际影响决定。

按 [output-schema.md](output-schema.md)提供正文与约束来源两端。可定位场景填 scene_id，跨场景问题用 null 交调用方；同一承载问题与 A 组归并，修复回到造成冲突的来源、装配或正文实现。
