# 连载大纲、人物与创作的上下文协议

本协议规定本包章内编排、人物派生、可选 actor、writer 与审阅之间的信息职责。文件字段分别由 [workspace-schema](../../serial-outline/references/workspace-schema.md)、[场景 schema](../../chapter-scene-plan/references/output-schema.md)、[role_view schema](../../role-brief-deriver/SKILL.md) 和 [role_move schema](../../character-rehearsal/references/output-schema.md) 拥有。调用顺序与失败路由见 [execution-protocol](execution-protocol.md)。

## 从来源到正文

```text
作者决定、既有正文与系列资料
             |
             v
卷纲本章意图 + 章卡选材范围
             |
             v
serial_context：作者侧脉络、设计方向、带来源的连续性资料
             |
             +--> 章内编排 --> phase5_scenes --> scene_card --> writer
             |                    |                            ^
             v                    v                            |
     合时人物来源 ------> 逐角色 role_view ---------------------+
                                  |                            |
                                  `--> 可选 actor --> role_move-+
                                                               |
                                                               v
                                                      正文 --> 现有审阅
```

`serial_context.md` 可含作者知道而人物未知的事实，以及尚未发生的卷向。它供编排、派生器、writer 和审阅读取；actor 只取得自己的 role_view。作者资料齐全与人物知情分别判断。

装配保留 story_bible 的已确认创作锚与风格、intent.current_thrust，并将 open_questions 单列为未决问题。编排与 writer 据已有方向组织本章，必要选择仍未定时只回交依赖它的部分；这些作者计划与表达判断不自动进入 role_view 的人物经历、所知或行动要求。

## 内容权威与实现裁量

| 内容 | 权威与用法 |
|---|---|
| 作者已确认的要求、冻结决定、既有正文与世界事实 | 保持其事实、适用条件和因果含义；彼此冲突时回交对应决定或来源环节，不能靠派生字段覆盖 |
| 卷纲与场景设计 | 说明本章/本场承担的冲突、变化、必要结果及后续承接；未来方向仍是设计，不能提前作为人物经历 |
| 人物基线、快照、传记和相关正文 | 按实际时点确定人物身份、经历、关系、能力与声音；保留条件、变化和未知范围 |
| role_view | 对上述人物资料与场景可见表面的派生；只编译已有依据，不能提升为新的事实权威 |
| 候选动作、物件、表达手法及 role_move | 为写作提供成立方式；writer 可更换、合并、调序或舍弃，保持事实、核心因果与必要结果 |

人物信念、惯用方法、职业经验与长期追求帮助理解选择；只有作者明确要求、原文确立的不能或当前实际条件才构成硬限制。一次犹疑不自动改写稳定人格，一次坚定也不证明任何处境下都绝不改变。角色资料中的 `forbidden` 等标签须保留其来源、对象与条件，不能把习惯和审美偏好一律升级成禁令。作者侧的不自觉欲望、弧光终点或诊断解释不进入人物当前自觉认知。

候选动作不成立但场景因果仍可成立时，writer 直接选择合适实现。必要事实缺失、人物知识不足以支持指定结果、或两个硬约束相冲突时，说明相关输入与冲突，回到来源或编排；不先写出不成立的正文再用措辞修补。

## 取得信息的时机

物化生成章目录、前章尾窗和初始通用上下文，尚未选择人物不等于已取得人物资料。编排前读当前卷纲的本章条目、前章衔接和已有角色/世界册索引，按本章需要填写已有章卡的 `recap_inputs` 与主 POV，然后装配。初始清单允许随设计细化；场景参与者或实体范围发生变化时更新章卡，编排结束回填场景索引并刷新受影响上下文。需要相同事实的既有有效材料直接复用，不建立重复选材报告。

场景投影同时保留“本场要改变什么”与候选实现的作用依据。`physical_carrier.function_link` 随候选承载物进入 scene_card，使 writer 能判断替换后是否仍成立；物件本身无独立保留权时可替换。`reader_yield` 用于判断信息与阅读效果，不能成为角色脑内旁白或逐项动作清单。

每次派生和写作都绑定明确的章 workspace、chapter_id 与 scene_id。章号只在系列内唯一；不能以“最近修改的目录”确定作品。明确加载本包职责后才按该职责的输入清单读取，不能假定裸名 writer 或 role-brief-deriver 已指向本包。

## 时间与知情范围

发布册的 `published_seq` 与未发布前章的 `prev_chapter` 链决定可用来源窗口；编号大小不证明先后。场景的 `location_time`、已定因果关系和原文决定故事时点。发布顺序、呈现顺序与故事时间各有用途：新章中的倒叙仍只能使用该历史时点成立的身份和知识。

- persona 的截止章、快照的覆盖章和传记章锚共同限定可用人物材料。合时基线先于完整卷快照时可单独使用；缺少材料时按需回读相关原文，不扩展基线来填满画像。
- 事实按 `established_at` 确定何时已有来源支持；秘密还须按 `known_by[].learned_at` 判断具体角色何时得知。普通事实出现在作者台账中也不等于人人知情，派生时仍需人物亲历、转述或可观察渠道。
- 章级事实段展示带来源的作者侧事实和在来源窗口内已登记的知情者，不以主 POV 删除其他人物所需事实。空知情者表示没有登记可用获知证据。role_view 只收录本角色合时信息；不用“角色不知道某秘密”来列出秘密内容。
- 最新续写可消费 facts_current；较早来源窗口从原台账筛选适用条目，再在该窗口内处理 supersedes。存量 retract/errata 没有完整发生时间时，受影响实体与属性的历史值留作待核，装配注明回读原文的位置，不能因排除作废行就推定旧事实已恢复。该视图不承担全世界状态重放。
- 已定稿但未发布的前章，仅沿当前 prev 链读取其仍有效的 recap 候选。来源不在该链、已失效的正文或当前场景的预定离场结果，不作为既有经历。当前章已经写出的相关场景，按故事时点和实际获知渠道参与派生；不强制回读全部正文。

`state.md` 和共享角色 runtime 包不保证随场景自动更新。它们在表达参考和当前已确认状态上有用；涉及动态事实时与合时人物台账及正文核对。writer 与 actor 通过 role_view 的 `character_basis` 取得本场可用的人物依据，不直接重读共享最新状态来覆盖切片。相同人物出现在不同时间的场景，切片可以不同。

## 人物绑定与职责交接

已有角色使用台账目录 `char_id`；runtime 包与显示名的对应须由 build-meta 的明确映射或既有人物资料确认。姓名相同、ID 不一致或映射含混时先定位既有来源，不猜拼音和 slug。接管人物可直接使用 persona、可见快照、传记及正文，不要求补造 Phase 2 或整套角色包。一次性功能角色由场景已明确的身份和当前情境建立依据，使用该章场景设计中明确、稳定的 participant ID；无需为一次出场建长期资产。

| 执行者 | 取得的材料 | 对下游负责的内容 |
|---|---|---|
| 章内编排 | 本章意图、选材后的 serial_context、按需来源 | 人物可成立的情境与核心因果，明确的参与者、故事时点和必要结果 |
| role-view 派生器 | 完整当前场景、作者侧上下文、按需合时人物与正文来源 | 每个人物独立的 character_basis、已知事实、可见刺激和实际限制；保持信息与指令的区别 |
| 可选 actor | 仅本人的 role_view；明确角色校验模式另加指定正文片段 | 该人物面对刺激的可选判断和行动；不消费全场结局、他人私密材料或作者解法 |
| writer | scene_card、serial_context、各角色 role_view、本次授权的可选 role_move、按条件参考 | 完整正文与人物之间真实发生的信息传递；不同人物的切片不能相互补全隐藏知识 |
| 现有审阅/修订 | 正文及问题涉及的设计、角色切片或来源 | 指出可定位的不符并回交负责环节；表达取舍和审美效果按既有作者权限处理 |

只有人物独有的经历、信念或信息会改变本场实现、且仍有实际选择空间时才使用 actor。场景已给出程序性结果、或 writer 凭既有材料可直接完成时沿直接写作路径。actor 的空 moves、未生成或普通生成失败不要求补齐；若其反馈指出 role_view 来源缺失或矛盾，先交派生或装配环节解决，再继续该场写作。writer 只读取本次 dispatch 明示的角色文件，旧 staging 产物不自动生效。

旧 role_briefs.md 的预填目标/心理/动作和旧 rehearsal 四项不能机械换名成 role_view 或 role_move。新链按来源重新派生当前场景，历史文件保持原样。后续修订仍在既有反馈路径中：来源或时点错回人物供给，因果/结果错回编排，措辞错交 writer/reviser；只更新受影响的切片与正文，不追加审计轮次。
