# 连载人物校验

## 用途与输入

审阅者已定位可能存在人物知识、声音或选择依据冲突的片段时，可调用本包 `serial-character-actor` 的 `mode: validation`。一次只针对一个角色与一个场景；本模式读取本人 `role_view` 和 dispatch 指定的正文片段，输入权限与写作前 role_move 模式分别执行。

提供 `{work_dir, scene_id, role_slug}`、需核对的具体位置及相关正文，使用 `pipeline/scene_{scene_id}/role_views/{role_slug}.yaml` 作为人物在入场时的依据。若该 view 已因上游修订失效，先由派生器更新；不能用共享角色包最新状态替代。片段太短，无法判断本场已经发生的获知或转变时，请审阅者补充直接相关的上下文，不自行阅读全章规划。

## 判断

从人物此时的经历、认识、语言能力和关系成本理解其言行，核对以下会改变修订决策的问题：

- 角色所用知识是否来自 view 的入场已知，或被审正文已实际建立的获知过程；正文新发生的事件可以改变原切片中的状态。
- 选择是否能由此人的前提与场内变化支撑；若人物违背习惯或承诺，正文是否给出了足以理解其变化的处境与代价。
- 说话对象、即时目的与声音是否相容；主动坦白、强烈情绪、沉默或直接说明都须按场内作用判断，不能因偏离惯常语气就判错。

反馈引用具体片段与来源依据。区分事实或知识矛盾、依据不足的选择、可成立的人物变化，以及仅属于审美偏好的候选改法。必要时给出改动方向，避免替所有角色统一润色成同一种声线。

## 反馈归位

将结果写入 `pipeline/staging/scene_{scene_id}/{role_slug}_validation.md`，回复完成及路径。当前审阅者核对证据后将实际问题并入既有审稿结果；角色视角的“像或不像”是定位线索，不独立触发重写、不直接覆盖人物台账或正文。

本模式接触成品片段用于核对，不回流为同场写作前候选，也不把正文里其他角色的私密叙述变成本人的已知。作品好坏和存在分歧的审美选择留给用户裁决。
